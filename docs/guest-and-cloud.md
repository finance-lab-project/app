# Guest and account budgets

Open the application root over HTTPS. Guests can enter income, investments and the ten starter spending categories. Save keeps the month in this browser profile. The page can save after loading even if the connection drops. An account unlocks category management and recorded Budget history.

After login, the transfer page lists saved local months. The owner can open the account directly or transfer the months. The transfer service processes each month in a separate version-checked Budget transaction. An existing month with differing values requires review. Blank fields preserve existing account values, including categories only present in the account. An explicit zero transfers as zero. A changed catalog requires review, and ambiguous category names require mapping. The browser removes a local copy only after a confirmed save and only if its contents still match. A failed or unconfirmed operation leaves the local copy available. On a second browser, sign in to the same configured account.

Responsive form layouts, labelled fields, visible keyboard focus, password-manager autocomplete, a password visibility control and a single primary action follow [Google Material button guidance](https://material-web.dev/components/button/) and [Google sign-in form guidance](https://web.dev/articles/sign-in-form-best-practices). Fonts and assets are served locally.

## HTTPS for the local preview

The sign-in form, transfer and account planner share one HTTPS origin. Use the same hostname and port for guest data and login. Set `APP_PUBLIC_ORIGIN` to that origin, including a nondefault port. Keep production Caddy on its automatic, publicly trusted certificate for the approved domain.

For a loopback preview supply a certificate for `localhost` from a locally trusted issuer (for example, a development certificate created with [Google's local HTTPS guide](https://web.dev/articles/how-to-use-local-https)). Point the local TLS listener at that certificate and key. A machine-specific test certificate or CA private key belongs outside source control. For an existing self-signed preview, pin its public certificate in a dedicated preview browser profile or explicitly trust only the verified localhost leaf for SSL on this Mac. Trust expires with the certificate. Verify the hostname and chain with `curl --fail --silent --output /dev/null https://localhost:8443/login` from a client that uses the chosen trust store. A test client configured to ignore certificate errors cannot verify this check.

## Russian personal data review

Reviewed on 7 November 2026 for one configured cloud account and a public guest page. The guest budget stays in Web Storage until the user chooses to transfer it. The proxy necessarily receives the client's network address and request metadata. The supplied proxy configuration omits access logging. Verify host, cloud and backup logging and their actual retention for the selected deployment. The sign-in page creates an essential session cookie. Account data includes the owner identifier, login configuration, categories, monthly amounts and change history. The runbook retains encrypted backups for 28 days.

An individual processing data exclusively for personal or family purposes may fall within the exception in Article 1(2)(1) if other people's rights are respected. A single configured account alone does not establish this exception for visitor information. Identify who operates the website and whether the actual processing qualifies. [Article 1](https://www.consultant.ru/document/cons_doc_LAW_61801/d44bdb356e6a691d0c72fef05ed16f68af0af9eb/)

If the operator collects identifiable visitors' data, identify the lawful basis for each purpose and publish the operator's policy and protection information on collection pages. The public guest form and login link to `/privacy`. Set `APP_PRIVACY_POLICY_FILE` to the operator's reviewed UTF-8 plain-text policy. Include the operator and contact, purposes, data, recipients/processors, storage and destruction periods, security measures, request/deletion procedure and any withdrawal procedure. The built-in storage notice describes app behavior. The operator supplies the facts specific to the deployment. [Article 6](https://www.consultant.ru/document/cons_doc_LAW_61801/315f051396c88f1e4f827ba3f2ae313d999a1873/) · [Article 18.1](https://www.consultant.ru/document/cons_doc_LAW_61801/eeeebe22bf738fd65bb66b95cc278911ae2525ee/)

When relying on consent, collect and retain demonstrable, specific consent separately from other confirmations. Acknowledging a cookie notice or pressing Sign in alone is insufficient evidence of such consent. The application has no optional analytics or advertising cookies. Assess any future optional tracking before enabling it. [Article 9](https://www.consultant.ru/document/cons_doc_LAW_61801/6c94959bc017ac80140621762d2ac59f6006b08c/)

Before processing subject to the law, check the Roskomnadzor notification duty and its exceptions, the database localization rules for Russian citizens, and actual processor, backup and cross-border arrangements. A planned Russian VM alone does not settle these questions.
